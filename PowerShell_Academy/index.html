POWERSHELL ESSENTIALS

Frequently asked questions

Answers to common PowerShell questions, from foundational concepts to Microsoft 365 administration.

What is PowerShell, and what is it used for?

PowerShell is a command-line shell, scripting language, and automation platform built on .NET. It helps you inspect systems, process files and data, manage services, automate repetitive work, and administer cloud technologies through modules and APIs. You can enter a single command interactively or combine many steps in a reusable script.

What is the difference between PowerShell and Command Prompt (CMD)?

Command Prompt is a traditional Windows command interpreter that usually works with text streams. PowerShell also runs commands, but its cmdlets generally return structured objects with properties and methods. That makes filtering, sorting, and combining results particularly useful. Both have legitimate uses, and PowerShell can also launch many external command-line tools.

Is PowerShell difficult to learn for beginners?

You can start with a few read-only commands and build up gradually. Learn Get-Command to discover commands, Get-Help for syntax and examples, and Get-Process to inspect results. The Academy's beginner lessons introduce those ideas before moving into objects, pipelines, functions, and automation.

What is the difference between Windows PowerShell 5.1 and PowerShell 7?

Windows PowerShell 5.1 is the older Windows-specific edition built on the .NET Framework. PowerShell 7 is the modern cross-platform edition built on current .NET and can run on Windows, macOS, and Linux. They can coexist on Windows, but some commands, modules, and behaviors differ. Check Microsoft's compatibility guidance before moving an existing script.

What are PowerShell cmdlets, functions, and scripts?

A cmdlet is a specialized PowerShell command, commonly named with a Verb-Noun pattern such as Get-Service. A function is reusable logic you define in PowerShell. A script is usually a .ps1 file containing commands and functions that work together. Modules can package and distribute cmdlets, functions, and other resources.

What is the PowerShell pipeline, and why is it useful?

The pipe symbol (|) sends output from one command to the next. PowerShell cmdlets commonly pass objects rather than merely passing text, so later commands can work directly with properties such as Name or CPU. For example, this pipeline sorts local processes by CPU time and shows the first three:

Get-Process | Sort-Object CPU -Descending |
  Select-Object -First 3 Name, CPU
How can PowerShell automate Microsoft 365 administration?

Microsoft provides PowerShell modules for services such as Microsoft Graph, Exchange Online, and Teams. Administrators use them to query users and groups, inspect mailboxes, review Teams settings, and automate approved tasks. Real administration requires the applicable module, sign-in, appropriate permissions, and an understanding of each command's impact. Start with read-only examples and official documentation.

What are PowerShell modules, and how do I install them?

A module is a package that makes commands, functions, and related functionality available to PowerShell. Use Get-Module -ListAvailable to inspect installed modules and Find-Module to discover packages in configured repositories. Depending on your tooling, installation may use Install-Module or Install-PSResource. Review a package's publisher, source, compatibility, and installation instructions before installing it. See Microsoft's module guide.

Can I practice PowerShell commands using this Academy?

Yes. Work through lessons, explore the curated command library, and use the Command Builder to prepare examples. The Practice Lab provides guided simulations with fictional data for its supported exercises; it does not run real PowerShell or connect to your computer or Microsoft 365 tenant. That distinction lets you study the command structure before trying it in a properly controlled environment.

How can I check whether a PowerShell script is safe before running it?

Read the script and understand what each command changes, verify the target paths and tenant, review required permissions, and avoid embedded credentials. Where a cmdlet supports it, -WhatIf can help preview certain changes, but it is not a guarantee that a complete script is safe. Use a separate test environment and code review; Microsoft's PSScriptAnalyzer can help with supported static checks. The Academy's Script Clinic supplies limited educational warnings, not a safety certification.
